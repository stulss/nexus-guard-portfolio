## Ⅳ. 심층 자기소개서 (Cover Letter & STAR Problem-Solving)

### [문항 1] 기존 시스템의 한계를 극복하고 완성도 높은 기술적 솔루션을 도출한 문제 해결 경험 (STAR 기법)
**"오탐과 의존성을 제거한 NIST 제로 트러스트 클린 베이스라인(Clean Slate) 보안 관제 솔루션 구축"**

* **Situation (상황):**  
  기존의 많은 보안 관제 도구나 학습용 오픈소스 프로젝트들은 최초 기동 시 시연용으로 하드코딩된 더미 공격자 데이터(`192.168.3.200`)나 임의의 감점 점수(65점)가 잔류하여, 실제 새 PC나 운영 환경에 설치했을 때 "시스템이 왜 시작부터 위험 상태인가?"라는 사용자 불신과 오탐(False Positive)을 초래했습니다. 또한 소스코드 기반 실행 방식은 파이썬 인터프리터 및 다양한 그래픽 라이브러리 종속성으로 인해 비개발자나 다른 환경에서 즉시 구동하기 어려운 높은 설치 장벽이 존재했습니다.

* **Task (과제):**  
  새로운 PC나 VM에 처음 설치했을 때 어떠한 이전 잔류 데이터도 없이 **'NIST SP 800-207 제로 트러스트 기준 텔레메트리 클린 베이스라인(100점 만점 / 활성 위협 0건 / 0% FP)'**의 무결한 신규 상태를 보장하는 독립형 네이티브 관제 소프트웨어를 완성하고, 파이썬이 없는 환경에서도 더블클릭 한 번으로 1초 만에 구동 가능한 상용화 수준의 패키징을 달성해야 했습니다.

* **Action (행동):**  
  1. **상태 머신 격리 및 비침습적 베이스라인 확립:** `FirewallRuleManager`, `FileIntegrityMonitor`, `ControlCenter` 등 코어 모듈의 인스턴스 초기화 로직을 전면 정비하여, 외부 이상 트래픽이 유입되기 전까지는 차단 목록 0건, 이상 징후 0점(기준선 100점)을 유지하도록 상태 머신을 격리했습니다. 호스트 자원을 고갈시킬 수 있는 정밀 취약점 스캔은 운영 안전성을 위해 관리자의 명시적 승인을 대기하도록 분리 설계하고, `test_clean_slate.py` 테스트를 작성하여 배포 전 0건 상태를 자동 검증했습니다.
  2. **직관적인 비전문가/CISO 친화적 UI/UX 혁신:** SentinelOne과 GlassWire의 직관적 UX를 벤치마킹하여, 360도 레이더에 4대 핵심 인프라 범례를 명시하고, 비전문가도 1초 만에 안전 여부를 파악할 수 있는 쉬운 한글 종합 판정 배너와 WCAG 2.x AA 고대비 가이드라인(대비율 4.5:1 이상)을 적용했습니다.
  3. **PyInstaller 및 GitHub Actions 자동 CI/CD 파이프라인 구축:** `scripts/build_exe.py`와 `build.bat`을 제작하여 17.5MB 단일 실행 파일(`NexusGuard.exe`)을 패키징하고, Git 태그 푸시 시 클라우드 러너에서 70개 전수 테스트를 통과해야만 GitHub Releases에 정식 배포 파일이 등록되는 자동화 체계를 완성했습니다.

* **Result (결과):**  
  신규 PC나 VM 어디서든 다운로드 후 더블클릭만으로 즉각 관제 콘솔이 실행되며, 100/100 만점의 클린 상태에서 실시간 트래픽 감시와 모의 침투 시연을 완벽하게 재현할 수 있는 상용화 수준의 엔터프라이즈 솔루션으로 인정받았습니다 (자동화 테스트 70/70 PASS, 결함률 0.0%).

**"단순 탐지를 넘어 즉각 격리와 0.8초 완전 복구를 실현한 차세대 Active Defense 체계"**

* **Situation (상황):**  
  전통적인 보안 체계는 방화벽에 기록된 로그를 사후에 분석하는 수동적 방식에 머물러 있어, 웹쉘 업로드나 기밀 파일(`.env`, `.git`) 탈취와 같은 고속 침해 행위를 실시간으로 막아내지 못했습니다. 또한 모의 침투 시연이나 방어 훈련 후 차단된 IP와 잠긴 계정을 일일이 수동으로 복구해야 하므로 운영 연속성과 테스트 재현성이 크게 떨어졌습니다.

* **Task (과제):**  
  침해 징후 포착 즉시 0.1초 만에 OS 커널 수준에서 공격자를 능동 격리하고, 시연이나 테스트가 끝난 후 시스템 환경을 1초 이내에 원래 클린 상태로 되돌리는 완전 자동화된 롤백(Rollback) 엔진을 구축해야 했습니다.

* **Action (행동):**  
  1. **디코이(허니팟) 카나리 트랩 및 OS 방화벽 연동:** 시스템 공격 표면에 공격자가 침투할 만한 미끼 경로 10종(`/.env`, `/.git`, `/admin.php` 등)을 전략적으로 배치했습니다. 정상 사용자는 이 경로를 호출할 이유가 없으므로 오탐률은 0.00%에 수렴합니다. 공격자가 단 1바이트라도 프로빙하는 즉시 0.1초 만에 OS 커널 방화벽(`netsh advfirewall`)을 호출하여 인바운드 패킷을 드롭하도록 구현했습니다.
  2. **디코이 우회 공격을 막아내는 3중 심층 방어선:** 정상 API로 우회 진입하는 지능형 공격에 대비하여, 2차 `AstQueryGuard`(동적 SQLi 차단), 3차 `BolaShield`(인가 및 결재 금액 변조 거부), 4차 `Groq AI-XDR`(비정상 행위 시맨틱 추론)의 연쇄 방어망을 구축했습니다.
  3. **0.8초 고속 원상복구(Clean-up) 엔진 개발:** 시연용으로 사용되는 고정 IP 8개와 테스트 계정 4개, 그리고 인메모리 블랙리스트를 원클릭으로 초기화하는 `demo_runner.py --cleanup` 스크립트를 제작했습니다.

* **Result (결과):**  
  디코이 탐침 즉시 **0.1초 만에 커널 방화벽 차단**이 집행되었으며, `demo_runner.py --cleanup` 실행 시 **단 0.80초 (실측 804.7ms)** 만에 차단 IP 해제 및 계정 잠금 해제가 완료되어 상용 제품 수준의 운영 안정성과 재현성을 입증했습니다.

---

### [문항 3] 4중 AI-XDR 하이브리드 엔진 설계 및 무중단 페일세이프 아키텍처 (STAR 기법)
**"클라우드 초고속 추론부터 폐쇄망 로컬 LLM까지 아우르는 4단계 캐스케이드 장애 복원력"**

* **Situation (상황):**  
  대규모 언어 모델(LLM) 기반의 차세대 XDR 시스템은 뛰어난 문맥 분석 능력을 제공하지만, 외부 API 호출 지연(Latency), 비용 한도 초과, 인터넷 장애 또는 군·금융권과 같은 망분리 폐쇄망 환경에서 솔루션 전체가 마비될 수 있는 구조적 취약성을 안고 있었습니다.

* **Task (과제):**  
  0.5초 이내의 실시간 초고속 위협 판정을 제공하면서도, 인터넷이 단절되거나 외부 AI 서비스 장애가 발생하더라도 관제 기능이 결코 중단되지 않는 100% 무중단 하이브리드 캐스케이드 AI 아키텍처를 완성해야 했습니다.

* **Action (행동):**  
  1. **4단계 AI 캐스케이드 라우팅 엔진 설계:**
     - **1순위 (초고속 LPU 추론):** Groq LPU 클라우드를 통해 0.5초 만에 복합 공격 체인을 1차 트리아지.
     - **2순위 (엔터프라이즈 정밀 추론):** NVIDIA NIM (Nemotron-70B) 클라우드 API를 연동하여 APT 다단계 공격 체인 심층 분석.
     - **3순위 (폐쇄망/망분리 환경):** Ollama 기반 로컬 LLM(`qwen2.5:7b`)을 127.0.0.1:11434로 연동하여 단 1바이트의 외부 데이터 유출 없이 온프레미스 추론 수행.
     - **4순위 (오프라인 무장애 폴백):** 모든 AI 인프라가 다운되더라도 시스템에 내장된 정규식 및 휴리스틱 룰 엔진으로 100% 자동 폴백(Graceful Degradation).
  2. **대량 트래픽 폭주 방어 큐 바운딩 (Bounded Queue):**
     - 동시 다발적인 보안 이벤트 폭주(Burst Traffic) 시 UI 스레드가 멈추는 것을 방지하기 위해 최대 500/10000건의 Bounded Queue 및 백프레셔 알고리즘을 적용했습니다 (`test_commercial_enterprise.py` 통과).

* **Result (결과):**  
  Groq LPU 실측 **0.48초**, NVIDIA NIM 실측 **0.52초**의 압도적인 AI 판정 속도를 달성하였으며, 5,000건의 동시 로그 폭주 시에도 UI 렌더링 프레임 타임 예산(16ms/60FPS)을 완벽히 방어하며 100% 무중단 관제 연속성을 실현했습니다.

### [문항 4] 이기종 인프라 연동과 크로스 도메인 기술 소통을 통한 보안 거버넌스 확립 (STAR 기법)
**"pfSense, Graylog, Wazuh, n8n을 하나로 엮어낸 표준 보안 스키마와 협업 거버넌스"**

* **Situation (상황):**  
  팀 프로젝트 "사내 인프라 종합 보안 방어전"에서 각 팀원은 네트워크 방화벽(이시헌), 중앙 SIEM(김태빈), Docker 가상화(진혜정), 웹/DB 하드닝(홍주형)으로 각기 다른 도메인을 담당했습니다. 그러나 팀원마다 사용하는 로그 포맷, IP 표기 방식, 심각도(Severity) 체계가 서로 달라 경계 방화벽에서 차단해야 할 IP가 SIEM에 제대로 인입되지 않거나 연동 병목이 발생하는 문제가 발생했습니다.

* **Task (과제):**  
  포털 코어 아키텍트이자 보안 최고관리자로서, 이기종 보안 솔루션들이 단일한 언어로 통신할 수 있는 표준화된 이벤트 규격을 제정하고, 다른 팀원들이 자신의 개발에만 전념할 수 있도록 완벽한 연동 런북과 접점(Interface)을 제공해야 했습니다.

* **Action (행동):**  
  1. **표준 보안 이벤트 스키마(`NX-SEC-01`) 제정:** 모든 보안 이벤트를 표준 JSON 규격(`ts, event_type, user, role, src_ip, method, path, decision, reason`)으로 단일화하고 총 86종의 보안 이벤트 목록을 문서화하여 Graylog 담당자에게 사전 배포했습니다.
  2. **324줄 마스터 연동 런북 작성:** WebGUI 클릭 경로, 입력 파라미터, 포트 맵, 페일세이프 방안을 총망라한 [`docs/EXTERNAL_INTEGRATIONS_GUIDE.md`](EXTERNAL_INTEGRATIONS_GUIDE.md)를 직접 작성하여 배포했습니다.
  3. **듀얼 모드 페일세이프 구축:** pfSense나 Wazuh 서버가 꺼져 있는 독립 PC 환경에서도 로컬 보안 엔진이 Standalone 상태로 즉시 전환되는 3-State 진단 로직을 개발하여 개발 단계의 블로커를 원천 제거했습니다.

* **Result (결과):**  
  팀 전체 연동 테스트에서 스키마 불일치로 인한 오류율 0%를 기록하였으며, pfSense 경계 차단부터 Graylog 상관분석, n8n 자동 티켓 발행, 그리고 NEXUS-GUARD 데스크톱 관제까지 전 계층이 한 치의 오차 없이 맞물려 돌아가는 엔터프라이즈 SOC 파이프라인을 완성했습니다.

## Ⅴ. 기술 면접관 적대적 질문 4선 & 모범 답변 플레이북 (CISO Q&A Playbook)

글로벌 테크기업 및 대형 핀테크 수석 기술면접관의 고난도 압박 질문에 대한 완벽한 방어 논리입니다:

### Q1. "기존의 상용 WAF(ModSecurity 등)가 있는데 왜 NEXUS-GUARD를 별도로 개발했습니까?"
* **모범 답변:**  
  "기존 상용 WAF는 패킷 페이로드 분석에 집중하지만, **현대 애플리케이션의 내부 맥락(Context)과 비즈니스 로직 결함(BOLA/IDOR)**은 네트워크 계층에서 볼 수 없습니다.  
  예를 들어 전자결재 단계 새치기나 지출결의서 품목 합계 위조는 정상적인 HTTP 200 POST 요청으로 유입되기 때문에 네트워크 WAF는 100% 통과시킵니다.  
  NEXUS-GUARD는 최외곽 디코이 트랩부터 소스코드 AST 정적 파서, BOLA 비즈니스 로직 실드, 그리고 0.5초 초고속 AI-XDR 트리아지까지 **'인프라-애플리케이션-비즈니스 로직' 전 계층을 수직 관통하는 능동형 통합 방어 체계**를 단일 에이전트로 완성하기 위해 개발했습니다."

---

### Q2. "부팅 즉시 100점 만점으로 시작하는 것이 눈속임이나 과장으로 보이지 않습니까?"
* **모범 답변:**  
  "NEXUS-GUARD의 '클린 슬레이트 100점'은 검사를 회피한 것이 아니라, **'NIST SP 800-207 제로 트러스트 기준 수신 텔레메트리 스트림에서 활성 이상 징후가 감지되지 않은 무결한 기준선(Operational Zero-Anomaly Baseline, 0% FP)'**을 의미합니다.  
  호스트의 CPU와 포트를 전수 검사하는 정밀 취약점 진단 점수는 운영 서버의 자원 보호를 위해 관리자의 명시적 승인을 대기하도록 의도적으로 분리 설계되었으며, 이는 CrowdStrike나 SentinelOne과 같은 상용 EDR의 'Baseline Clean State' 개념과 완벽히 부합합니다."

---

### Q3. "디코이(/.env)를 건드리지 않고 실제 API 엔드포인트로 직접 침투하는 지능형 공격은 어떻게 방어합니까?"
* **모범 답변:**  
  "디코이는 유일한 방패가 아니라 '0% 오탐의 조기 경보 카나리'입니다. 인터넷 침해 시도의 99% 이상을 차지하는 자동화 스캐너를 최외곽에서 0.1초 만에 걸러내어 SOC 관제사의 피로도를 제로로 만듭니다.  
  만약 고도화된 공격자가 디코이를 건드리지 않고 정상 API 엔드포인트로 진입하더라도, 2차 방어선인 **AST Query Guard**가 파라미터화되지 않은 동적 SQL 쿼리를 차단하고, 3차 방어선인 **BOLA Shield**가 세션 소유권 및 결재 단계 무결성을 강제하며, 4차 방어선인 **Groq AI-XDR**이 비정상 행위 시맨틱을 0.5초 만에 판정하여 커널 격리를 집행하는 3중 심층 방어선(Defense-in-Depth)이 대기하고 있습니다."

---

### Q4. "외부 SIEM(Graylog)이나 EDR(Wazuh) 장비가 없는 영세 기업이나 독립 PC 환경에서는 무용지물 아닌가요?"
* **모범 답변:**  
  "NEXUS-GUARD는 **'엔터프라이즈 풀 연동 및 Standalone 페일세이프 듀얼 모드'**를 완벽히 구현했습니다.  
  대기업 엔터프라이즈 환경에서는 pfSense, Graylog, Wazuh, n8n과의 풀 스택 연동으로 SOC 관제 센터와 유기적으로 동작하지만, 인프라가 전혀 없는 환경에서는 **자체 SHA-256 FIM 엔진, Windows netsh 커널 방화벽 제어기, 로컬 Ollama AI 및 내장 휴리스틱 룰 엔진**이 100% 독립 가동되어 단 1바이트의 외부 통신 없이도 완벽한 엔드포인트 능동 방어를 완수합니다."

---

## Ⅵ. 직무 철학 및 엔지니어링 비전 (Engineering Philosophy & Vision)

> **"보안은 공격을 막는 것뿐만 아니라, 정상 상태를 오탐 없이 신뢰할 수 있게 증명(Clean Slate)하는 것에서 출발합니다."**

보안 시스템이 현장에서 외면받는 가장 큰 이유는 과도한 오탐(False Positive)으로 현업 개발자와 관제사를 지치게 하거나, 정작 장애 발생 시 운영 환경을 신속하게 롤백할 수 없는 비가역적 구조에 있습니다.  
저는 코드 한 줄을 작성하더라도 **'오탐률 0%의 조기 경보 카나리'**, **'0.8초 만에 시스템을 정상화하는 롤백 메커니즘'**, 그리고 **'비전문가도 1초 만에 이해할 수 있는 직관적인 시각화'**를 집요하게 추구합니다.  
귀사에 합류하여 글로벌 수준의 보안 아키텍처와 엔터프라이즈 방어 체계를 구축하는 데 저의 모든 역량과 열정을 쏟아붓겠습니다.
